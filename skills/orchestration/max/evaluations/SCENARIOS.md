# Max evaluation specifications

Specifications, not executed platform tests.

| Scenario | Expected behavior |
|---|---|
| @MAX implement a complex authorized task | Max and Delegate once in registry selection; two distinct coordinated cycles and fresh goal audit. |
| Calculate maximum bending moment | No Max activation from incidental maximum. |
| @max without a known goal | Ask for objective; no dispatch. |
| @ask @max ambiguous build | Intent confirmation before workers or changes. |
| Cycle 1 accepted | Cycle 2 challenges exact candidate; preserves verified work. |
| Cycle 2 finds integration defect | Targeted repair and exact-candidate recheck. |
| Goal auditor finds defect after 10/10 prior cycle | Reject and route defect; no prior score priming. |
| 10/10 with essential check unverified | FAIL regardless of score. |
| Three outer fix rounds exhausted | Gap Report; no certification or loop restart. |
| Native workers unavailable | Two sequential role cycles and separate self-review; no fake independence. |
| Independent audit explicitly required but unavailable | Blocked/provisional, not independent PASS. |
| Delegate instructions inaccessible | Disclose compliance blocker. |
| @max @3d @animate | One coordinator; all separate gates on final revision. |
| @max @review read-only source audit | Report is candidate; no changes to reviewed source. |
| User prohibits runtime tests | Respect exclusion; distinguish static evidence and unverified essentials. |
